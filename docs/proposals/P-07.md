# P-07 NotificationDeliveryFailed reaches no end

status: accepted A
found by: end-of-flow check (zenwave-tasks-from-code-and-models check mode, claude-opus), 2026-11-14
flow: place-order-flow
blocks: none (T-42 sets the Notification FAILED and emits NotificationDeliveryFailed)

## Problem
The three send commands declare `withEvents [...Sent | NotificationDeliveryFailed]`
([notifications-consumer-domain-model.zdl:88-98](../../../arcadia-editions-modulith-api/notifications-consumer-domain-model.zdl#L88)),
but the ZFL has no branch for `NotificationDeliveryFailed`
([place-order-flow.zfl:189-202](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L189),
[:257-266](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L257)) and no end outcome for it.
When the e-mail provider refuses, the flow stops: nobody listens, a redelivery over FAILED is a no-op, the customer
is never told and no end is reached.

## Evidence
[check-board.md](../../.zenwave/handoff/place-order-flow/reports/check-board.md) (M-2),
[review-S1-r2.md](../../.zenwave/handoff/place-order-flow/reports/review-S1-r2.md) (NOTE: a FAILED notification is
never retried).

## Options
- A: ZFL end `notificationFailed: NotificationDeliveryFailed` on the three send steps (a terminal outcome for ops).
  Changes: ZFL only.
- B: a retry policy first (attempt count on Notification, retried by a timer), then A when exhausted.
  Changes: ZDL entity + command, ZFL timer and end.
- C: accept: the order outcome stands, an alert on FAILED notifications is enough. Changes: ZFL comment.

Recommendation: A now; B when a real e-mail provider (T-33) shows how often it refuses.

## Decision
A, decided by the person on 2026-11-17. Changes in the models on branch `fix/payment-reauthorize-transitions` (arcadia-editions-modulith-api, arcadia-editions-architecture):
each send step in the ZFL has `@outcome(sent)` and `@failure @outcome(failed) emits NotificationDeliveryFailed`; the ZFL `end` adds
`notificationFailed: NotificationDeliveryFailed` (its `type` tells which business outcome). B (retry) deferred to the real e-mail provider (T-33).
New baseline follows.
