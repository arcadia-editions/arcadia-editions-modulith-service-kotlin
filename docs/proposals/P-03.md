# P-03 The checkout API has no answer for "stock unavailable"

status: open
found by: zenwave-tasks-from-code-and-models, claude opus, 2026-11-12
flow: place-order-flow
blocks: T-15

## Problem
When stock is gone, [place-order-flow.zfl:199](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L199)
says "no order record was created", and `startOrderCheckout` emits `StockUnavailable`
([orders-checkout-domain-model.zdl:98](../../../arcadia-editions-modulith-api/orders-checkout-domain-model.zdl#L98)).
But `POST /orders/start-checkout`
([orders-checkout-openapi.yml:44](../../../arcadia-editions-modulith-api/orders-checkout-openapi.yml#L44)) only
declares `201` with an `Order` and `400`. There is no response for a request that is valid but cannot be served,
and no `Order` to return.

## Evidence
Chain `C-07` (SKU-003, available 0): the web test for the stock-gone path has no status or body to assert.

## Options
- A: `409 Conflict` with a `StockUnavailable` body (`orderId`, `unavailableItems`). Changes: OpenAPI; regenerate
  the web adapter; fixtures unchanged.
- B: `201` with an `Order` in a new status (e.g. `REJECTED`), persisted. Changes: ZDL `OrderStatus`, the ZFL
  sentence, OpenAPI; fixtures (C-07 gets an order).
- C: `202 Accepted` for every checkout, with the result only through events/notifications. Changes: OpenAPI, ZFL.

Recommendation: A. It keeps "no order record" and gives the client what to render.
