# P-08 A refused void has no outcome

status: open
found by: end-of-flow check (claude-opus), 2026-11-14; first seen in reviews S6 and S6-r2
flow: place-order-flow
blocks: none (the fake processor always approves voids)

## Problem
`voidPayment` compensates `authorizePayment` and declares only `withEvents PaymentVoided`
([payments-processing-domain-model.zdl:97-100](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L97),
[place-order-flow.zfl:204-215](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L204)).
When the processor refuses the void, the code throws: the event publication stays incomplete and is resubmitted
every 30 s once older than PT5M, forever. Stock is never released, the order never cancelled, no end is reached.

## Evidence
[check-board.md](../../.zenwave/handoff/place-order-flow/reports/check-board.md) (M-3),
[review-S6.md](../../.zenwave/handoff/place-order-flow/reports/review-S6.md) (NOTE T-27). The reviews filed it under
P-05, but P-05 is about redelivered PaymentFailed and names no void outcome.

## Options
- A: `VOID_FAILED` state and a `PaymentVoidFailed` event that `releaseStock` also listens to, so the order is
  cancelled anyway and ops follow up the authorization by hand. Changes: ZDL state + event + listener, ZFL branch.
- B: a bounded retry of the void (attempts on Payment), then A. Changes: as A plus a counter and a timer.
- C: keep throwing and alert on stale publications. Changes: none in the models.

Recommendation: A. The customer's order and the stock should not wait on the processor.
