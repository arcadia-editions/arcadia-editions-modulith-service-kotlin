# P-02 Outcome states are the target of no @transition

status: open
found by: zenwave-test-scenarios (coverage matrix, lifecycle preconditions), claude opus, 2026-11-12
flow: place-order-flow
blocks: none (tasks follow assumption A-01 of the data.sql header until decided)

## Problem
Several commands declare one target state but emit alternative outcomes whose states other commands start from:

- `authorizePayment` `@transition(to: AUTHORIZATION_REQUESTED)`
  ([payments-processing-domain-model.zdl:86](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L86))
  emits `PaymentAuthorized | PaymentDeclined | PaymentFailed`, yet `capturePayment` starts from `AUTHORIZED`
  ([:94](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L94)) and `retryPayment` from
  `FAILED` ([:90](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L90)). No transition
  reaches `AUTHORIZED`, `DECLINED` or (from authorize) `FAILED`.
- `capturePayment` `@transition(from: AUTHORIZED, to: CAPTURED)` emits `PaymentCaptureFailed`, and `voidPayment`
  starts from `CAPTURE_FAILED` ([:99](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L99)),
  which nothing reaches.
- `scheduleFulfillment` `@transition(to: SCHEDULED)`
  ([fulfillment-shipping-domain-model.zdl:83](../../../arcadia-editions-modulith-api/fulfillment-shipping-domain-model.zdl#L83))
  emits `FulfillmentFailed`; `FAILED` is reached by no transition.
- `send*` `@transition(to: PENDING)`
  ([notifications-consumer-domain-model.zdl:89](../../../arcadia-editions-modulith-api/notifications-consumer-domain-model.zdl#L89))
  emit `...Sent | NotificationDeliveryFailed`; `SENT` and `FAILED` are reached by no transition.

## Evidence
data.sql chains `C-04` (Payment AUTHORIZED), `C-12` (FAILED), `C-17` (CAPTURE_FAILED), `C-16` (Fulfillment FAILED),
`C-06` (Notification SENT) hold states the lifecycles cannot reach. The generated `*Transitions.kt` guards accept them,
but no generated code sets them.

## Options
- A: list every outcome state in the target, e.g. `@transition(to: [AUTHORIZED, DECLINED, FAILED])`,
  `@transition(from: AUTHORIZED, to: [CAPTURED, CAPTURE_FAILED])`, `@transition(to: [SCHEDULED, FAILED])`,
  `@transition(to: [SENT, FAILED])`. Changes: ZDL only; regenerate; fixtures unchanged.
- B: keep the models; the implementation sets the state named after the outcome event (assumption A-01).

Recommendation: A, it makes the state machines in the projections complete. B is what the board assumes meanwhile;
switching to A changes no task.
