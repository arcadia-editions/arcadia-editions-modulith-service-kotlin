# P-05 A redelivered PaymentFailed cannot be told apart from a new failure

status: open
found by: T-22 (implementer claude-opus), checked by the orchestrator, 2026-11-13
flow: place-order-flow
blocks: none (T-22 is merged; redelivery behavior below is what the code does today)

## Problem
`retryPayment` listens to `PaymentFailed`
([payments-processing-domain-model.zdl:89](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L89))
with `RetryPaymentInput { orderId }`
([:65](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L65)). The Payment stays `FAILED`
while it is retried (`@transition(from: FAILED, to: [FAILED, RETRY_EXHAUSTED])`), so a second delivery of the same
`PaymentFailed` finds the same state and retries again: `attemptCount` goes up twice and two `PaymentRetried` are
emitted for one failure. After `RETRY_EXHAUSTED` a redelivery throws `InvalidStateTransitionException`.
Every other command of the flow treats a redelivery as a no-op; this one cannot.

## Evidence
`PaymentFailed` already carries `attemptCount`
([:124-130](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L124)), but the input drops it.
Spring Modulith's event publication registry redelivers incomplete publications on restart (at-least-once).
T-22 report: [T-22.md](../../.zenwave/handoff/place-order-flow/reports/T-22.md) (CHOICES).

## Options
- A: add `attemptCount Integer required` to `RetryPaymentInput`; `retryPayment` does nothing when
  `payment.attemptCount > input.attemptCount` (already retried for that failure) or the Payment is `RETRY_EXHAUSTED`.
  Changes: ZDL input, regenerate payments (listener mapper fills it from the event); fixtures unchanged.
- B: no model change; make `RETRY_EXHAUSTED` a no-op in code and accept a double retry on redelivery (bounded by
  the 3-attempt limit). Changes: code only.
- C: keep the input; dedupe by the event publication id (store the last processed `PaymentFailed` per Payment).
  Changes: entity field or side table; more code.

Recommendation: A. The event already has the data; the check is one comparison.
