# P-01 PaymentRetried cannot feed authorizePayment

status: open
found by: zenwave-tasks-from-code-and-models (lint zdl.data-lineage), claude opus, 2026-11-12
flow: place-order-flow
blocks: T-23 (T-24 and T-25 wait on it)

## Problem
[place-order-flow.zfl:132](../../../arcadia-editions-architecture/business-flows/place-order-flow.zfl#L132) feeds
`PaymentRetried` back into `authorizePayment`, and
[payments-processing-domain-model.zdl:85](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L85)
declares that listener. But `AuthorizePaymentInput`
([payments-processing-domain-model.zdl:56](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L56))
requires `amount`, `currency`, `customerEmail` and `paymentMethodId`, and `PaymentRetried`
([payments-processing-domain-model.zdl:133](../../../arcadia-editions-modulith-api/payments-processing-domain-model.zdl#L133))
carries only `orderId`, `customerId`, `attemptCount`, `retriedAt`.

## Evidence
`bash .zenwave/bin/lint-zdl.sh --strict` reports 4 `zdl.data-lineage` warnings on line 85. A retry test on chain
`C-12` (Payment FAILED, attempt 1) cannot build a valid `AuthorizePaymentInput` from the event.

## Options
- A: a separate command for the retry path, e.g. `reauthorizePayment(ReauthorizePaymentInput { orderId })`
  `@listener(event: PaymentRetried) @transition(from: FAILED, ...)`, that loads the Payment by `orderId` (it already
  holds amount, currency, e-mail and payment method). ZFL line 132 calls it instead of `authorizePayment`.
  Changes: ZDL (new input + method), ZFL line 132, regenerate payments; fixtures unchanged.
- B: add `amount`, `currency`, `customerEmail`, `paymentMethodId` to `PaymentRetried`.
  Changes: ZDL event; regenerate payments; fixtures unchanged.
- C: make those `AuthorizePaymentInput` fields optional and load them from the Payment when absent.
  Changes: ZDL input; weakens the OrderCreated path validation.

Recommendation: A. `authorizePayment` creates the payment (`@transition(to: AUTHORIZATION_REQUESTED)`); a retry
works on an existing one, from FAILED, which is a different transition.
